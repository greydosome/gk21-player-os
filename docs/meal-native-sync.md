# 기존 식단 항목으로 대화 섭취 반영

2026-11-12 변경: 확정 식단 원장은 출처·수정 이력을 유지하며, `body_record`의 기존 음식 목록에 투영한다. 기존 카탈로그에 정확히 대응하고 수량을 확인한 음식은 단백질/탄수화물/지방 항목을 사용한다. 나머지는 일반식의 이름·수량·열량으로 저장한다. 일반식 열량도 기존 화면과 기간 합계에 들어간다. 미확인 열량은 빈 인코딩 필드/null이며 ‘열량 미확인’으로 표시하고 합계에서는 제외한다. 일반식의 식재료를 별도 음식으로 중복 추가하지 않는다.

`meal_native_sync`는 날짜별 자동관리 항목과 수동변경 보호 상태를 저장한다. 동일 원장 재반영 시 이전 자동항목을 제거한 뒤 최신값을 적용한다. 사용자가 변경·삭제한 항목 또는 기존 동일 음식은 덮어쓰거나 다시 추가하지 않고 충돌로 남긴다. 같은 이름·끼니에 식사를 추가하는 경우 현재 구현은 중복 가능성을 우선 차단하므로 `native_conflicts`를 확인한다. 이전 revision의 열린 화면이 자동저장하면 409로 막고 새로고침을 안내한다.

원장의 영양 출처·추정 표시는 식단의 접힌 ‘자동 기록의 영양정보 출처’에서 확인한다. 카탈로그 음식의 열량은 GK21 기존 카탈로그 기준(예: 달걀 1개 100kcal)이며 독립적으로 검증한 제조사 영양표가 아니다. 새 식사의 카탈로그가 명확하지 않으면 임의 유사상품을 선택하지 않는다. 음식명/수량 모호성은 원장에 보존한다.

## 실행 계정과 배포

Mac 현재 계정으로 로컬 격리 PostgreSQL 시험 및 Next 빌드. VM rocky가 앱 `/home/rocky/gk21`을 실행. root가 백업·서비스 재시작, postgres가 `/postgres/scripts/migrations/2026-11-12_meal_native.sql` 적용 및 `gk21_app`에 새 테이블 SELECT/INSERT/UPDATE 권한 부여. 업로드키는 기존 root 전용파일에 그대로 두며 출력·복사하지 않는다. DB 데이터 `/postgres`는 이동하지 않는다. 기존 MCP 수정은 변경하지 않는다.

기존 확정 식사만 `meal_native.sync`로 한 번 투영한다. 합성 기록은 운영 DB에 넣지 않는다. 추가 식단 POST는 같은 트랜잭션에서 원장과 기존 항목을 함께 갱신한다. 날짜 정정은 이전 날짜와 새 날짜 모두 반영한다. 자동화는 매일 한국 시간 08:00/16:00/19:00, Mac/Codex 온라인에서 기존 CLI를 사용한다.

## 검증

격리 DB의 원장 중복·정정·삭제, 기존 달걀 카탈로그 재사용, 수량 변환, unknown 열량 보존, 수동 변경/삭제 보호 및 오래 열린 화면의 저장 차단을 검사한다. TypeScript 및 production build 검사. 운영은 원본 식사와 기존 음식 배열·칼로리, 앱 화면을 비교한다.

## 롤백

`/var/backups/gk21-meal-native-20261112/`에 배포 직전 소스, DB dump, 기존 frontend 빌드를 보관한다. 소스와 빌드는 변경 파일만 복구하고 backend/frontend를 재시작한다. 운영 중 생긴 수동 기록이 있으므로 전체 DB dump를 덮어쓰지 않는다. 자동 반영 항목의 데이터 롤백은 `meal_native_sync.state`의 managed 문자열과 현재 항목이 정확히 일치하는 경우만 제거하고 catalog kcal 기여분만 뺀다. 수동 변경 항목은 보존한다. 새 원장/동기화 테이블은 삭제하지 않는다.
