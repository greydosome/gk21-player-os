# 운동 완료 대화 → 기존 GK21 기록

## 입력 범위

설정한 운동 코치 대화에서 **사용자가 운동을 실제로 완료했다고 보고한 메시지**만 처리한다.
계획, 질문, 추천, 가정, 인사 및 운동 결과가 없는 대화는 건너뛴다.
AI가 제안한 운동 목록을 완료 기록으로 바꾸지 않는다. 개인 원문·이미지는 서버에 복사하지 않는다.

## 기존 항목 병합

- 완료 보고에 종목이 있고 같은 날짜의 워치 세션이 하나로 식별되면 그 세션을 구체화한다.
  예: 합성 시험의 근력운동 20분 + 런지 완료 → 하체운동 20분·런지 체크.
- 운동 시간은 워치의 실제 지속 시간을 우선한다. 새 운동을 한 건 더 만들지 않는다.
- 워치에 기록하지 않았다고 명시한 운동은 별도 세션으로 추가한다.
- 워치 기록보다 대화가 먼저 와도, 나중에 같은 세션이 도착하면 대화 항목을 보완한다.
- 시간 정보가 전혀 없으면 기존 분 입력은 0으로 두고 종목만 체크한다. 이때 0은 시간이 미입력이라는 뜻이며 임의의 기본 시간을 넣지 않는다.
- 같은 메시지를 다시 처리해도 중복 추가하지 않는다. 후속 시간 정정은 같은 session_key와 새 메시지 ID로 보낸다.
- 같은 날 후보 세션이 여러 개이거나 한 세션의 부위별 시간을 구분할 수 없으면 매칭을 보류한다.
- 직접 수정한 운동 시간·삭제 기록은 자동 재수집으로 되돌리지 않는다.

## 서버

마이그레이션: `2026-11-10_workout_conversation_reports.sql`.
기능 스위치: `WORKOUT_CONVERSATION_ENABLED=true`.
HTTPS `POST /api/integrations/workout-reports`는 기존 건강 전송 키로 인증한다.
날짜·사용자 메시지 ID·완료 여부·기존 운동 분류·체크 항목·알려진 시간만 받는다.
GET의 날짜별 상태는 처리한 메시지와 보류 상태 및 워치 세션 후보를 반환한다.
신체 경로, 심박 및 일반 대화 원문을 저장하지 않는다.

## 대화 연결

로컬 Codex 후속 자동화가 15분마다 지정한 운동 코치 대화의 새 사용자 메시지를 읽고 완료 결과만 구조화한다.
`scripts/sync_workout_conversation.py`는 구조화된 보고를 HTTPS로 전송한다.
전송 키와 처리 체크포인트는 저장소 밖 개인 설정 폴더에 보관한다.
직접 HTTPS 연결이 회사 망에서 차단되면 `--ssh-host`로 기존 승인된 서버 연결을 사용한다.
이 경우 키는 서버의 root 전용 파일에서만 읽으며 Mac으로 가져오지 않는다.
실행할 때는 로컬 컴퓨터와 Codex가 사용 가능해야 한다. 서버가 ChatGPT 대화를 직접 구독하는 웹훅이 아니다.
운동 결과가 없거나 이미 처리했으면 아무 기록도 바꾸지 않고 조용히 종료한다.
일반 처리 결과를 매번 사용자에게 알리지 않는다. 전송 실패나 판단 불가 상태만 내부에 남겨 재시도한다.

## 확인 사항

격리된 PostgreSQL에서 워치 보완, 대화 선도착, 미기록 운동 추가, 중복 재실행,
수동 수정 보호 및 계획·질문·빈 보고 건너뛰기를 검사한다.
백엔드 전체 49개 검사를 통과했고, 운영 HTTPS에서도 질문 보고를 보내 기존 운동과 보고 행이 바뀌지 않음을 확인했다.
실제 대화에서 운동 완료가 보고되기 전에는 합성 운동을 운영 기록에 추가하지 않는다.
